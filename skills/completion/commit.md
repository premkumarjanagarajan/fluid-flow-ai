# Commit

Generate a conventional commit message and change summary artifact for the current initiative. This produces a **file** — it does NOT execute the commit. The actual commit happens only after the consolidated human gate in the completion skill.

## When to Run

Called by the completion skill (Batch 2). Not invoked directly by the orchestrator.

## Prerequisites

- Implementation is complete
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/` exists with metadata and artefacts
- Source repo(s) have uncommitted changes on the working branch

## Execution

### 1. Resolve Template

Follow the template resolution chain in order. Use the **first** template found:

#### Priority 1 — Enterprise KB (department/domain)

Launch `skills/kb-retrieval/kb-retrieval.skill.md` as a subagent with the query:

> "Commit message template or commit artifact template for department {DEPARTMENT}"

If the KB returns a template (not a gap report), use it.

#### Priority 2 — Local Knowledge Base

If `LOCAL_KB_MANIFEST` is set, check:

```
{DEPT_FF_PATH}/knowledge-base-local/templates/commit.template.md
```

If the file exists, use it.

#### Priority 3 — Fallback (built-in)

Use `skills/completion/templates/commit.template.md`.

When the fallback is used, present a one-time notice after the artifact is generated:

```
ℹ Using the built-in commit template. You can customise this for your
  department by creating one of:

  • Enterprise-wide: Add a commit template to your department's KB folder
    in betsson-kb-docs (e.g. knowledge/departments/{dept}/engineering/templates/commit.template.md)
    and register it in your department overlay.

  • Department-local: Create the file at:
    {DEPT_FF_PATH}/knowledge-base-local/templates/commit.template.md

  Local templates take effect immediately. Enterprise templates are shared
  across all teams in the department.
```

Store a flag (`COMMIT_TEMPLATE_NOTICE_SHOWN`) so this notice is only shown once per session.

---

### 2. Gather Context

Load the following (skip any that don't exist):

- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/spec.md` — feature scope
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/plan.md` — planned approach
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/tasks.md` — task breakdown
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/metadata/state.md` — workflow progression
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/security/vapt-report.md` — security findings (if exists)
- JIRA ticket context from `JIRA_KEYS[]` (if available)

### 3. Obtain the Diff

```bash
git diff --stat HEAD
git diff --cached --stat
```

Capture the list of changed files, insertions, and deletions.

### 4. Generate Conventional Commit Message

Follow the [Conventional Commits](https://www.conventionalcommits.org/) specification:

```
{type}({scope}): {description}

{body}

{footer}
```

| Field | Rule |
|-------|------|
| **type** | `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `perf`, `ci`, `build` — inferred from the workflow and changes |
| **scope** | Short identifier for the area affected (component, module, package). Omit if changes span many areas. |
| **description** | Imperative mood, lowercase, no period, max 72 chars |
| **body** | Bullet-point summary of what changed and why. Wrap at 100 chars. |
| **footer** | JIRA references (`Refs: DIT-179`), breaking changes (`BREAKING CHANGE:`), co-authors if applicable |

### 5. Generate the Artifact

Create the directory `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/operations/` if it does not exist.

Write to: `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/operations/commit.md`

Populate the resolved template by replacing all `{PLACEHOLDER}` tokens with actual values. If the resolved template contains sections or fields not listed here, populate them using the gathered context or mark as "N/A".

**Mandatory footer** — regardless of which template was resolved, always ensure the artifact ends with:

```
---
*Generated by Fluid Flow {FF_VERSION}*
```

Replace `{FF_VERSION}` with the current Fluid Flow version (from the orchestrator banner). If the resolved template already contains this footer, do not duplicate it.

### 6. Return

Return the commit message and artifact path to the caller. Do NOT execute `git commit`.
