# PR

Generate a pull request description and metadata artifact for the current initiative. This produces a **file** — it does NOT create the PR. The actual PR creation happens only after the consolidated human gate in the completion skill.

## When to Run

Called by the completion skill (Batch 2). Not invoked directly by the orchestrator.

## Prerequisites

- Implementation is complete
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/` exists with metadata and artefacts
- Branch exists and has commits ahead of the base branch

## Execution

### 1. Resolve Template

Follow the template resolution chain in order. Use the **first** template found:

#### Priority 1 — Enterprise KB (department/domain)

Launch `skills/kb-retrieval/kb-retrieval.skill.md` as a subagent with the query:

> "Pull request template or PR description template for department {DEPARTMENT}"

If the KB returns a template (not a gap report), use it.

#### Priority 2 — Local Knowledge Base

If `LOCAL_KB_MANIFEST` is set, check:

```
{DEPT_FF_PATH}/knowledge-base-local/templates/pr.template.md
```

If the file exists, use it.

#### Priority 3 — Fallback (built-in)

Use `skills/completion/templates/pr.template.md`.

When the fallback is used, present a one-time notice after the artifact is generated:

```
ℹ Using the built-in PR template. You can customise this for your
  department by creating one of:

  • Enterprise-wide: Add a PR template to your department's KB folder
    in betsson-kb-docs (e.g. knowledge/departments/{dept}/engineering/templates/pr.template.md)
    and register it in your department overlay.

  • Department-local: Create the file at:
    {DEPT_FF_PATH}/knowledge-base-local/templates/pr.template.md

  Local templates take effect immediately. Enterprise templates are shared
  across all teams in the department.
```

Store a flag (`PR_TEMPLATE_NOTICE_SHOWN`) so this notice is only shown once per session.

---

### 2. Gather Context

Load the following (skip any that don't exist):

- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/spec.md` — feature scope and requirements
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/plan.md` — planned approach
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/tasks.md` — task breakdown and completion status
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/operations/risk-report.md` — risk assessment (if generated)
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/security/vapt-report.md` — security findings (if exists)
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/metadata/state.md` — workflow progression
- `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/metadata/analytics.md` — timing metrics (if exists)
- JIRA ticket context from `JIRA_KEYS[]` (if available)

### 3. Determine PR Metadata

| Field | Source |
|-------|--------|
| **Title** | Conventional commit subject line, or `{type}({scope}): {description}` from spec |
| **Base branch** | `main` (or detect from repo's default branch) |
| **Head branch** | Current working branch |
| **Labels** | Infer from workflow: `feature`, `bugfix`, `refactor`, etc. Add `ai-assisted`. Add `security-reviewed` if VAPT passed. |
| **Reviewers** | Leave empty — the user assigns reviewers manually |
| **JIRA link** | Format JIRA keys as links if the JIRA base URL is known from MCP config |

### 4. Generate the Artifact

Create the directory `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/operations/` if it does not exist.

Write to: `{DEPT_FF_PATH}/initiatives/{INITIATIVE_NAME}/artefacts/operations/pr.md`

Populate the resolved template by replacing all `{PLACEHOLDER}` tokens with actual values. If the resolved template contains sections or fields not listed here, populate them using the gathered context or mark as "N/A".

**Mandatory footer** — regardless of which template was resolved, always ensure the artifact ends with:

```
---
*Generated by Fluid Flow {FF_VERSION}*
```

Replace `{FF_VERSION}` with the current Fluid Flow version (from the orchestrator banner). If the resolved template already contains this footer, do not duplicate it.

### 5. Return

Return the PR title, metadata, and artifact path to the caller. Do NOT create the PR or push.
